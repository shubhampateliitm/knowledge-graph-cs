@@ ssh
value: SSH gives you a secure remote shell, file copy and port forwarding over an untrusted network. It replaced telnet and rsh, which sent passwords in clear text.
how: The client and server agree session keys with Diffie-Hellman, the server signs the exchange with its host key, the user proves identity with a key signature or password, and then many channels share one encrypted TCP connection.
intuition: A sealed tube between two rooms: anyone can see the tube, nobody can see what moves inside.
friction: Users skip host-key checks (trust on first use); long-lived keys spread across servers and are hard to rotate.
ref: spec | RFC 4253: The Secure Shell (SSH) Transport Layer Protocol | Ylonen & Lonvick, IETF 2006 | https://www.rfc-editor.org/rfc/rfc4253

@@ dhcp
value: DHCP gives a new device an IP address, a gateway and DNS servers automatically, so nobody has to configure every laptop and phone by hand.
how: The device broadcasts DISCOVER over UDP, a server answers with an OFFER, the device sends REQUEST and the server confirms with ACK. The address is a lease that the device renews halfway through its lifetime.
intuition: A hotel front desk that hands out room numbers on arrival and takes them back at checkout.
friction: Anyone on the link can run a rogue DHCP server; leases that are too short cause churn, too long waste addresses.
ref: spec | RFC 2131: Dynamic Host Configuration Protocol | Droms, IETF 1997 | https://www.rfc-editor.org/rfc/rfc2131

@@ wifi
value: Wi-Fi (IEEE 802.11) carries Ethernet-like frames over radio, so phones and laptops join a local network without cables.
how: Stations listen before sending and back off for a random time to share one channel; data is spread over many OFDM subcarriers with error-correcting codes, and WPA2/WPA3 encrypts and authenticates every frame.
intuition: A crowded room where everyone waits for a quiet moment before speaking.
friction: Shared airtime: one slow or distant device slows everyone; walls, microwaves and neighbours cause interference.
ref: book | 802.11 Wireless Networks: The Definitive Guide | Gast, O'Reilly 2005 |

@@ usb
value: USB is the standard bus for connecting keyboards, storage, cameras and chargers to a computer, with one connector type and automatic device setup.
how: The host controller polls devices on a tiered tree. Each device describes itself with descriptors when plugged in, and data moves in control, bulk, interrupt or isochronous transfers.
intuition: A teacher who asks each pupil in turn whether they have something to say.
friction: Polling adds latency; power and cable quality vary; USB-C cables look alike but support very different speeds.
ref: spec | USB specifications | USB Implementers Forum | https://www.usb.org/documents

@@ nfc
value: NFC lets a phone or card talk to a reader a few centimetres away, for payments, transit cards, door badges and security keys.
how: The reader's 13.56 MHz magnetic field powers a passive chip; the chip answers by changing how much power it draws (load modulation), and a secure element runs signed protocols such as EMV.
intuition: A torch that both lights a mirror and reads the flicker the mirror sends back.
friction: Range is only a few centimetres by design; relay attacks can stretch it; readers and phones differ in antenna placement.
ref: spec | NFC Forum specifications | NFC Forum |

@@ display
value: A display turns bytes in memory into light. Every frame you see was read out of a framebuffer by a display controller at a fixed refresh rate.
how: The controller scans the framebuffer line by line and drives each pixel's LCD or OLED element; double buffering and vsync swap frames between refreshes so you never see half of one frame and half of the next.
intuition: A printer that redraws the whole page, top to bottom, 60 to 240 times a second.
friction: Latency from buffering, tearing without vsync, and high bandwidth: 4K at 120 Hz is roughly 30 Gbit/s of pixels.
ref: docs | Linux kernel DRM/KMS documentation | kernel.org | https://docs.kernel.org/gpu/index.html

@@ authn
value: Authentication proves who a user is, once, and then carries that proof on every later request, so apps can trust that a request really comes from that person.
how: The user shows a password plus a one-time code, or a passkey that signs a server challenge with a private key kept on the device. The server then issues a session cookie or a signed token; single sign-on lets one identity provider do this for many apps.
intuition: A hotel checks your passport once at the desk, then gives you a key card for the rest of your stay.
friction: Passwords get phished and reused; tokens are hard to revoke before they expire; account recovery is often the weakest path.
ref: spec | Web Authentication (WebAuthn) Level 2 | W3C, 2021 | https://www.w3.org/TR/webauthn-2/

@@ sns
value: Amazon SNS sends one message to many receivers. A publisher sends a message to a topic once, and SNS pushes a copy to every subscriber: SQS queues, Lambda functions, HTTP endpoints, email or SMS.
how: Subscribers register on a topic. When a message arrives, SNS stores it in several availability zones and then pushes a copy to each subscriber. Failed pushes are retried with backoff and can go to a dead-letter queue. Filter policies let each subscriber receive only the messages it wants.
intuition: A radio station: it broadcasts once, and every radio tuned to it hears the message.
friction: SNS does not keep messages for later readers; a subscriber that is down misses pushes unless it reads through an SQS queue. Delivery is at least once, so receivers must handle duplicates.
ref: docs | Amazon SNS Developer Guide | AWS | https://docs.aws.amazon.com/sns/latest/dg/welcome.html
