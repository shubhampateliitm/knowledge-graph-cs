@@ llm
value: Large language models are transformers trained to predict the next token of text, at enormous scale. That simple objective turned out to produce systems that can summarize, translate, answer questions, write and debug code, follow instructions, and reason through multi-step problems. Since the 2017 transformer paper and GPT-3 (2020), LLMs have become a general-purpose interface to software: you describe what you want in plain language, and the model produces text, code or structured calls that other software can execute.
Their value is generality. One pretrained model, adapted with instructions, examples or light fine-tuning, replaces thousands of special-purpose NLP systems. Combined with retrieval (RAG), tools and agents, they extend from 'talking' to 'doing'.
how: Text is first split into tokens (sub-words, usually by byte-pair encoding), and each token becomes an embedding vector. The model is a stack of identical blocks. Each block has a self-attention layer, in which every token computes a query, key and value vector and takes a weighted average of earlier tokens' values, weighted by how well its query matches their keys, followed by a feed-forward network (often a mixture of experts, where a router sends each token to a few expert networks). Residual connections and normalization keep the deep stack trainable; positional information is injected with schemes like RoPE.
Training happens in stages. Pretraining minimizes cross-entropy loss on next-token prediction over trillions of tokens, using gradient descent (Adam-style optimizers), backpropagation, mixed precision and thousands of GPUs or TPUs working in parallel (data, tensor and pipeline parallelism with all-reduce). Scaling laws, measured by Kaplan et al. (2020) and refined by the Chinchilla work (2022), show loss falling predictably as a power law with more parameters, data and compute. Post-training then shapes behavior: supervised fine-tuning on examples, and reinforcement learning from human or AI feedback (RLHF, RLAIF, Constitutional AI, DPO) to make the model helpful, honest and harmless. Reasoning models are further trained with RL to produce long chains of thought before answering.
At inference, the model generates one token at a time. The keys and values of earlier tokens are kept in a KV cache, so each new token costs work proportional to the context length rather than recomputing everything. Decoding turns probabilities into text with greedy choice or sampling (temperature, top-p). Serving systems batch many users' requests together (continuous batching), store the KV cache in pages (PagedAttention), reuse shared prefixes (prompt caching), quantize weights to 8 or 4 bits, and use speculative decoding to go faster.
How the lower layers add value: attention, embeddings and the KV cache (Layer 2) are the core mechanisms; GPU tensor cores and HBM bandwidth (Layer 3) are what make them affordable; linear algebra, calculus, probability and information theory (Layer 4) are the language of the whole model; and the end of Dennard scaling and the physics of chips (Layer 5) explain why AI progress is now limited by power and memory bandwidth.
intuition: To predict the next word of a detective novel's last chapter, you need to have understood the plot. Next-token prediction is easy to state but, at scale, forces the model to build internal representations of grammar, facts, style, and some reasoning, because those help predict text. Attention is the mechanism that lets each word 'look back' and gather exactly the context it needs. Post-training is like an apprenticeship after a very broad education: it teaches the model what kind of assistant to be.
friction: LLMs can state falsehoods fluently (hallucination), are sensitive to wording, and can be manipulated by text in their inputs (prompt injection). Their knowledge has a cutoff date. Attention's cost grows with context length, so very long contexts are expensive, and quality can drop in the middle of long inputs. Evaluation is hard: benchmarks leak into training data and saturate quickly. Training costs hundreds of millions of dollars and huge energy budgets. Interpretability, meaning knowing why a model produced an answer, is an active research area. Model names and versions change every few months (in October 2026, GPT-6 and Claude 5.x generations are current, and Google has said Gemini 4 will launch before the end of the year), so treat any comparison as dated.

@@ agents
value: An AI agent is an LLM placed in a loop where it can take actions: call tools, read the results, and decide what to do next until a goal is reached. Chat answers questions; agents complete tasks. A coding agent can read a repository, run tests, edit files and open a pull request. A data agent can query a warehouse, notice an anomaly and draft a report. The value is turning language understanding into work done, with humans supervising instead of typing every step.
how: The core loop, popularized by the ReAct paper (2022), is: think about the goal and current state, choose an action (a tool call), observe the result, and repeat. Tools are described to the model with names, descriptions and JSON schemas. The model emits a structured call; the host program validates it, runs it (often in a sandbox), and appends the result to the context. Protocols standardize this: the Model Context Protocol (MCP, Anthropic, 2024; now under the Linux Foundation's Agentic AI Foundation) connects AI applications to tool and data servers over JSON-RPC; A2A connects agents to other agents.
Context engineering is the craft of deciding what goes into the model's limited context window at each step: instructions, relevant files or documents (often fetched with retrieval), summaries of earlier steps, tool results and memory. Long-running agents use prompt caching to reuse the unchanged prefix cheaply, and checkpoint their progress so they can resume. Orchestration frameworks (LangGraph and others) structure multi-step and multi-agent workflows. Evaluation uses task suites with real environments (SWE-bench for code, for example).
How the lower layers add value: LLMs (Layer 1) supply the reasoning; tool calling, ReAct and context engineering (Layer 2) structure it; HTTP, parsing and OS sandboxes (namespaces, cgroups) at Layer 3 make tool use safe and practical; control theory (Layer 4) is the shape of the loop; and computability (Layers 3 and 5) explains a hard limit: no program can decide in general what arbitrary code will do, so permission systems and sandboxes are essential.
intuition: An agent is a capable new colleague with no memory between conversations and a strong desire to help. Give them a clear goal, the right tools, a scratchpad, and permission boundaries, and they do impressive work. Give them vague goals, too many tools or untrusted instructions hidden in a web page, and they can go confidently in the wrong direction. Good agent design is mostly good delegation: clear scope, checkpoints, and verification.
friction: Errors compound over many steps: a small mistake early can derail a long task. Agents are non-deterministic, which makes testing and reproducibility hard. Prompt injection, where malicious instructions hide in tool results, is a serious security problem; agents with access to email, code or money need least-privilege permissions and human approval for risky actions. Costs and latency grow with every loop iteration. Long tasks exceed context windows and need summarization or memory systems that can lose information. And evaluation is still immature: success on a benchmark does not guarantee success in your environment.

@@ attention
value: Attention lets every token in a sequence gather information from every other relevant token, in one step, with weights learned from data. Before transformers, recurrent networks passed information token by token, which was slow (no parallelism across the sequence) and forgetful over long distances. Self-attention made sequence models parallel to train on GPUs and good at long-range dependencies, which is why it now underlies language models, vision transformers, speech models, protein models like AlphaFold, and most of modern AI.
how: Each token's embedding x is projected by three learned matrices into a query q, a key k and a value v. For token i, the model computes a score between q_i and every k_j (a dot product, divided by the square root of the dimension to keep values in a good range), turns the scores into weights with a softmax so they are positive and sum to one, and outputs the weighted sum of the v_j. In matrix form: softmax(QKᵀ/√d)·V. In a decoder-only LLM, a causal mask stops tokens from attending to future positions.
Multi-head attention runs several of these in parallel with different projections, so different heads can track different relationships (syntax, coreference, position). Grouped-query and multi-query attention share keys and values across heads to shrink the KV cache. Position is added through encodings such as RoPE, which rotates q and k by angles that depend on position, so their dot product depends on relative distance.
The cost is quadratic: n tokens means n² scores. In practice the bottleneck is memory traffic, not arithmetic. FlashAttention (2022) computes attention in tiles that fit in the GPU's fast on-chip SRAM, using an online softmax so the full n×n matrix is never written to slow HBM memory, which gives large speed-ups without changing the result. At inference, keys and values of past tokens are cached (the KV cache), so each new token attends to stored vectors instead of recomputing them.
How the lower layers add value: matrix multiplication on tensor cores (Layer 3) makes QKᵀ fast; HBM bandwidth (Layer 3) limits it; linear algebra and probability (Layer 4) are its language (dot products as similarity, softmax as a probability distribution); and distributional semantics (Layer 5) explains why learned vector similarity captures meaning at all.
intuition: Reading the sentence 'The trophy didn't fit in the suitcase because it was too big', you resolve 'it' by looking back at 'trophy' and 'suitcase' and asking which fits 'too big'. Attention is a learned version of that look-back: each word asks a question (query), every other word advertises what it has (key), and the best matches send their information (value). It is a soft, differentiable dictionary lookup.
friction: Quadratic cost in context length is the main friction: long contexts are expensive in compute and especially in KV-cache memory. Many alternatives (linear attention, state-space models such as Mamba, sliding-window and sparse attention, hybrids) try to reduce it, with trade-offs in quality. Attention weights are often presented as explanations, but research shows they are not reliable explanations of model decisions. And models can underuse information in the middle of very long contexts.

@@ gd
value: Gradient descent is how almost every machine-learning model learns. You define a loss (a number that says how wrong the model is), and gradient descent repeatedly nudges the model's parameters in the direction that reduces the loss fastest. It works for a linear regression with two parameters and for a language model with a trillion. Its value is generality: if you can write the model as a differentiable computation and the loss as a number, you can train it.
how: The gradient of the loss with respect to the parameters is a vector pointing uphill; step the parameters a small amount (the learning rate) in the opposite direction, and the loss usually goes down. Computing the exact gradient over all data is too expensive, so stochastic gradient descent (SGD) estimates it on a small random batch each step; the noise even helps escape poor regions. Momentum keeps a running average of past gradients to smooth the path. Adam (2014) also keeps a running average of squared gradients to give each parameter its own adaptive step size; AdamW decouples weight decay. Learning-rate schedules (warm-up, then cosine or linear decay) matter a lot in practice.
The gradients themselves come from backpropagation: the chain rule applied in reverse through the computation graph, so computing all gradients costs only a small constant times the cost of computing the loss. Frameworks like PyTorch and JAX do this automatically (autodiff). For huge models, the batch is split across many GPUs, each computes gradients on its share, and an all-reduce sums them before the update.
How the lower layers add value: calculus and the chain rule (Layer 4) make gradients cheap; optimization theory (Layer 4) explains convergence in convex problems and gives tools like learning-rate bounds; probability and statistics explain why mini-batch estimates work; floating-point and mixed precision (Layer 3) make the arithmetic fast but approximate; and GPUs (Layer 3) make the matrix products affordable.
intuition: You are on a foggy mountain at night and want to reach the valley. You cannot see the landscape, but you can feel the slope under your feet. Take a step downhill, feel again, repeat. A large learning rate means long strides (fast, but you may overshoot and bounce around); a small one means careful shuffles (safe, but slow). Momentum is like a rolling ball that keeps going through small bumps.
friction: Deep-learning loss landscapes are not convex, so there is no guarantee of reaching the best solution, yet in practice large networks train well, and theory is still explaining why. Training is sensitive to learning rate, batch size, initialization and normalization; instabilities (loss spikes, exploding or vanishing gradients) waste expensive compute. Gradient descent needs differentiable models; discrete choices need tricks (reinforcement learning, relaxations). And it is data-hungry: it learns slowly compared with how quickly humans learn from few examples.

@@ consensus
value: Consensus is how a group of machines agrees on a single value, or a single order of operations, even when some of them crash or messages are delayed. It is the foundation of every strongly consistent distributed system: leader election, distributed locks, configuration stores (etcd, ZooKeeper, KRaft), replicated databases (Spanner, CockroachDB, TiDB) and Kubernetes' control plane. Without consensus, two machines could both believe they are the leader, and data would diverge.
how: The standard model is crash-fault tolerance: nodes may stop, messages may be delayed, lost or reordered, but nodes do not lie. With 2f+1 nodes, the system tolerates f failures, because any two majorities (f+1 nodes) must share at least one node; that shared node carries knowledge of earlier decisions forward. Protocols such as Paxos (Lamport, submitted 1990, published 1998), Viewstamped Replication (1988), ZAB (ZooKeeper) and Raft (2014) all use majorities, a leader, and a way to tell old leaders from new ones (ballot numbers, epochs or terms).
In practice, systems use consensus to agree on a replicated log ('state machine replication'): if every replica applies the same commands in the same order, they all reach the same state. A leader proposes log entries; an entry is committed once a majority has stored it durably; then it is applied. Reads need care: either go through the log, or use leases or read-index checks to be sure the leader is still the leader.
Two famous results set the limits. The FLP impossibility result (1985) shows that in a fully asynchronous system, no deterministic protocol can guarantee consensus if even one node may crash, so practical protocols rely on timeouts and are guaranteed safe always but live only when the network behaves. The CAP theorem says that during a network partition you must choose between consistency and availability; consensus systems choose consistency, and the minority side stops accepting writes. For nodes that may act maliciously, Byzantine fault-tolerant protocols (PBFT, and blockchain consensus) need 3f+1 nodes.
How the lower layers add value: TCP and timeouts (Layer 3) provide the messaging and failure detection; fsync (Layer 3) makes votes durable; combinatorics (Layer 4) proves majorities overlap; logic and induction (Layer 4) prove safety; and relativity (Layer 5) explains why there is no global clock to make this easy.
intuition: A committee of five votes on decisions. As long as three agree, a decision stands, and because any two groups of three must share a member, no two contradictory decisions can both get three votes. If the chair disappears, the committee elects a new chair with a higher term number, and anything the old chair says afterwards is ignored. Consensus protocols are that committee, written down carefully enough that a machine can follow it during network chaos.
friction: Consensus costs latency: every write needs a round trip to a majority, and across regions that is tens of milliseconds. Throughput is bounded by the leader. Membership changes, disk stalls, clock problems with leases, and network asymmetries cause subtle bugs; even well-known implementations have had correctness bugs found by tools like Jepsen. Many systems therefore use consensus only for metadata (who leads what), and use cheaper replication for bulk data.

@@ raft
value: Raft is a consensus algorithm designed to be understandable. Paxos had been the standard for decades, but it was notoriously hard to learn and even harder to turn into a complete system. Diego Ongaro and John Ousterhout published Raft in 2014 with the explicit goal of making consensus teachable and implementable, and it worked: etcd (and so Kubernetes), Consul, CockroachDB, TiKV, Kafka's KRaft, Redpanda and many others use Raft.
how: Raft separates the problem into three parts. Leader election: every node is a follower, candidate or leader. Followers expect regular heartbeats; if one hears nothing within a randomized timeout, it becomes a candidate, increments the term number, votes for itself and asks others for votes. A node grants at most one vote per term, and only to a candidate whose log is at least as up to date as its own. A candidate with a majority becomes leader. Randomized timeouts make split votes rare.
Log replication: clients send commands to the leader, which appends them to its log and sends AppendEntries messages to followers. Each message includes the index and term of the preceding entry, so a follower can detect gaps or conflicts and the leader can back up and repair them. Once an entry from the current term is stored on a majority, the leader marks it committed, applies it to its state machine, and tells followers.
Safety: the election rule guarantees that any new leader already has every committed entry, so committed entries are never lost. Terms act as a logical clock: messages from older terms are rejected, which stops a deposed leader from causing harm. The paper also covers membership changes (joint consensus or single-server changes) and log compaction with snapshots.
How the lower layers add value: durable writes with fsync and sequential logs (Layer 3) make votes and entries survive crashes; TCP and timers (Layer 3) carry heartbeats; majorities overlapping (Layer 4 combinatorics) is the core safety argument; and proofs by induction over terms (Layer 4) establish correctness, with TLA+ specifications used to check it.
intuition: Raft is a class with a class monitor. If the monitor goes quiet for too long, a student stands up and says 'I'm the monitor for term 7, vote for me'. Students vote once per term and only for someone whose notebook is at least as complete as theirs. The winner reads out instructions; everyone copies them into their notebook; an instruction counts once more than half the class has written it down.
friction: Raft's leader is a throughput and latency bottleneck, and every write costs a majority round trip. Performance depends heavily on disk fsync latency. Leader changes cause brief unavailability, and badly tuned timeouts cause flapping leaders. Implementations must handle many details the core paper treats lightly: pre-vote to avoid disruption by partitioned nodes, read leases, snapshots, and membership changes. Running thousands of Raft groups (one per range or partition, as CockroachDB and TiKV do) needs batching and heartbeat coalescing.
