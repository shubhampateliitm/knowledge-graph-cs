@@ tcp
value: TCP (Cerf and Kahn, 1974; standardized 1981) turns an unreliable network that drops, duplicates and reorders packets into a reliable, ordered stream of bytes between two programs. Almost everything on this map talks over it: HTTP/1 and HTTP/2, database connections, Kafka replication, Spark shuffles, gRPC, SSH. Its value is that application developers can write to a socket as if writing to a file, and the bytes arrive complete and in order, or the connection reports an error.
how: A connection starts with a three-way handshake (SYN, SYN-ACK, ACK) that agrees on starting sequence numbers. Every byte has a sequence number; the receiver sends cumulative acknowledgements; the sender retransmits data that is not acknowledged within a timeout estimated from measured round-trip times, or sooner on duplicate acknowledgements (fast retransmit). The receiver advertises a window of how much buffer it has free (flow control), so a fast sender cannot overwhelm a slow receiver.
Congestion control protects the network itself. TCP starts slowly (slow start doubles the sending window every round trip), then grows linearly and cuts back sharply when it detects loss: additive increase, multiplicative decrease (Jacobson, 1988). Modern variants include CUBIC (the Linux default) and BBR (Google, 2016), which estimates bottleneck bandwidth and round-trip time instead of waiting for losses. Throughput is roughly window size divided by round-trip time, which is why long-distance connections need large windows.
TCP's ordered-stream model causes head-of-line blocking: one lost packet stalls all data behind it. HTTP/2 multiplexes many streams over one TCP connection, so a single loss stalls them all; QUIC (HTTP/3) moves reliability per stream into user space over UDP to avoid this, and combines the transport and TLS handshakes.
How the lower layers add value: IP routing (Layer 3) delivers packets best-effort; control theory and queueing theory (Layer 4) describe congestion control as a feedback loop around router queues; probability (Layer 4) models loss; and the speed of light (Layer 5) sets the round-trip time that bounds how fast any TCP connection can ramp up.
intuition: You are dictating a long letter over a bad phone line. You number each sentence; the listener says 'got up to sentence 41'; if they say 41 three times, you repeat 42. You start speaking slowly and speed up while it's going well, and slow down sharply when they miss things, both to help them and to avoid jamming a line shared with others.
friction: The handshake costs a round trip before any data moves (two or more with TLS 1.2), which hurts short connections and is why connection pooling and keep-alive matter. Slow start makes new connections slow on high-bandwidth, high-latency paths. Head-of-line blocking hurts multiplexed protocols. Tail latency suffers from retransmission timeouts. Middleboxes (firewalls, NATs) ossify TCP, making changes hard to deploy, one reason QUIC runs over UDP. In data centres, incast (many senders replying to one receiver at once, as in a scatter–gather query) overflows switch buffers and causes timeouts.

@@ vmem
value: Virtual memory gives every process the illusion of its own large, private, contiguous memory, starting at address zero, regardless of how much physical RAM exists or where its pages really live. It provides isolation (one process cannot read another's memory), simplicity (programs use simple addresses), efficiency (memory is shared where possible, for example libraries and copy-on-write after fork) and flexibility (files can be mapped into memory, and rarely used pages can be moved to disk). It is so successful that the same idea reappears elsewhere: vLLM's PagedAttention is virtual memory for the KV cache.
how: Memory is divided into fixed-size pages (usually 4 KB; 2 MB or 1 GB 'huge pages' also exist). Each process has a page table that maps virtual page numbers to physical frames, plus permission bits (read, write, execute). The CPU's memory management unit translates every address through this table. Because walking a multi-level page table on every access would be slow, recent translations are cached in the TLB (translation lookaside buffer). A TLB miss costs a page-table walk; a page fault, when the page is not in RAM or not yet allocated, traps into the kernel, which allocates or loads the page and resumes the program.
The kernel uses this machinery for many features: demand paging (allocate memory only when touched), copy-on-write (fork shares pages until one side writes), memory-mapped files (mmap, used heavily by Lucene and databases), the page cache (file data cached in RAM and shared by all processes), swapping, and guard pages that catch stack overflows.
How the lower layers add value: the memory hierarchy (Layer 3) makes the TLB and caches essential; probability and locality of reference (Layer 4) explain why caching translations and pages works: programs reuse nearby addresses; and hardware support built from digital logic (Layer 3) makes translation happen on every memory access without software involvement.
intuition: Each process gets its own street map with its own house numbers. A post office (the MMU) translates 'house 12 on my street' into the real location in the city. The post office keeps a small notebook of recent translations (the TLB). If you visit a house that hasn't been built yet, the city builds it on the spot (page fault, demand paging).
friction: TLB misses and page faults are invisible but costly; large-memory workloads (databases, JVMs, ML) often need huge pages to reduce TLB pressure. Swapping turns memory pressure into dramatic slowdowns. Overcommit means allocations can succeed and then fail later (the Linux OOM killer). mmap-based I/O makes error handling and control over flushing difficult, which is why some databases avoid it. Security bugs such as Meltdown (2018) exploited the boundary between user and kernel memory and forced costly mitigations.

@@ memhier
value: The memory hierarchy is the single most important performance fact in computing. CPUs can do an operation in well under a nanosecond, but fetching data from main memory takes around 100 ns, from an SSD around 100 µs, and from another continent around 100 ms. Computers bridge this gap with layers of storage, each bigger, slower and cheaper than the one above: registers, L1, L2 and L3 caches, DRAM, SSD, disk, network storage. Nearly every performance technique on this map exists to keep the right data in the fast layers.
how: Approximate access times on a modern server: register under 1 ns; L1 cache (32–64 KB per core) about 1 ns; L2 (around 1–2 MB) about 3–5 ns; L3 (tens to hundreds of MB, shared) about 10–20 ns; DRAM about 80–100 ns; NVMe SSD read about 20–100 µs; a round trip within a data centre about 0.5 ms; across a continent tens of milliseconds. Caches move data in 64-byte lines. They work because programs show locality: temporal (recently used data is likely to be used again) and spatial (nearby data is likely to be used soon). Hardware prefetchers detect sequential access patterns and fetch ahead.
Software follows the same principle at every level: CPU caches, the OS page cache, database buffer pools, Redis in front of a database, CDNs in front of origins, and GPUs with registers, shared memory, L2 and HBM. Data structures are designed around it: B-trees match disk pages, columnar formats fill cache lines with useful values, and FlashAttention tiles computations to fit in on-chip SRAM.
How the lower layers add value: probability (Layer 4) describes hit rates and reuse distances; queueing (Layer 4) explains contention for shared caches and memory bandwidth; and physics (Layer 5) explains why the hierarchy exists at all: signals travel about 20 cm per nanosecond in wires, larger memories are physically further away and need longer wires with more capacitance, and DRAM cells are capacitors that must be read and refreshed.
intuition: Your desk holds the few papers you are using now; your drawer holds this week's files; the office filing room holds this year's; the warehouse across town holds everything else. Fetching from the warehouse takes a day. Good work habits (keep what you need close, fetch in big batches, put related things together) are exactly what caches, prefetching and columnar layouts do.
friction: The gap keeps growing: CPU speed improved much faster than memory latency for decades ('the memory wall'), and now memory bandwidth limits AI more than compute ('the bandwidth wall'). Cache behavior is invisible in code, so small changes (struct layout, access order, false sharing between threads) can make code several times slower. Multicore adds cache coherence traffic and NUMA effects. Benchmarks that fit in cache mislead about production performance.

@@ linalg
value: Linear algebra is the mathematics of vectors and matrices, and it is the working language of machine learning, graphics, signal processing, search and much of scientific computing. A neural network layer is a matrix multiplication followed by a simple non-linear function. An embedding is a vector. Similarity search is about distances and angles between vectors. Recommendation can be done by factorizing a user–item matrix. GPUs and TPUs are, at heart, machines for multiplying matrices quickly.
how: A vector is a list of numbers that can be read as a point or a direction in space. A matrix is a linear transformation: it rotates, stretches, projects or mixes the coordinates of vectors. Multiplying matrices composes transformations. The dot product measures how aligned two vectors are (cosine similarity is the normalized dot product), which is exactly what attention scores and vector search compute.
Key ideas: linear independence and rank (how many independent directions a matrix really uses: LoRA assumes weight updates have low rank); eigenvectors and eigenvalues (directions a transformation only stretches: PageRank is the main eigenvector of the link matrix); the singular value decomposition, which writes any matrix as rotation × scaling × rotation and gives the best low-rank approximation (used for compression, PCA and latent semantic analysis); and projections (least-squares regression projects data onto a subspace).
Computing with matrices is a field of its own: dense matrix multiplication costs about n³ operations naively, and it is organized in blocks so data stays in caches and registers; BLAS libraries, cuBLAS and tensor cores implement this. Numerical stability matters: some computations amplify rounding errors (ill-conditioned matrices).
How the lower layers add value: real numbers and calculus (Layer 4) give the field its foundations; and in physics (Layer 5), linear algebra is the language of quantum mechanics, where states are vectors and observables are matrices.
intuition: A matrix is a machine that takes an arrow and returns a new arrow. Stack machines and you get a composite machine, which is just another matrix. A neural network is a long chain of such machines with small 'bends' (non-linearities) in between; training adjusts the numbers inside each machine so the final arrows point where we want.
friction: Linear algebra is easy to manipulate symbolically and hard to feel geometrically, which is why visual courses like 3Blue1Brown's help so much. In high dimensions, intuition fails: almost all random vectors are nearly perpendicular, and distances concentrate, which affects nearest-neighbour search. Large matrix computations are limited by memory bandwidth more than arithmetic, and low-precision formats (FP8, FP4) save time but need care to avoid accuracy loss.

@@ probability
value: Probability is the mathematics of uncertainty. Computer systems are full of it: random hashing, packet loss, request arrivals, failures, sampling, A/B tests, approximate data structures, randomized algorithms, and above all machine learning, where models output probability distributions and are trained by maximizing likelihood. Probability lets engineers make precise statements about things that are not certain: 'this bloom filter has a 1% false-positive rate', 'this cluster loses data less than once in a million years', 'variant B is better with 95% confidence'.
how: A probability distribution assigns likelihoods to outcomes. Random variables have expected values (averages) and variances (spread). Independence means one event tells you nothing about another; conditional probability and Bayes' rule describe how evidence updates beliefs. Key distributions appear constantly: uniform (good hash outputs), Bernoulli and binomial (successes and failures), Poisson (arrivals per second), exponential (time between arrivals or failures), normal (averages of many things), and heavy-tailed distributions such as power laws (popularity, file sizes, latency tails).
Several results do a lot of work. Linearity of expectation makes many analyses easy. The law of large numbers and the central limit theorem explain why averages over many samples are stable and roughly normal, which justifies sampling, A/B testing and monitoring. Concentration bounds (Chernoff, Hoeffding) bound how far a sum strays from its mean, which underlies randomized algorithms and learning theory. The birthday bound says collisions among random values appear after about the square root of the number of possible values.
How the lower layers add value: set theory and measure theory (Layer 4, Kolmogorov 1933) give probability its rigorous foundation; and at Layer 5, epistemology asks what probabilities mean (frequencies or degrees of belief), while quantum mechanics shows that randomness is built into nature itself.
intuition: Probability is bookkeeping for ignorance. You do not know which server will fail tomorrow, but you can know roughly how many will fail this year, and design for that. Most of engineering's reliability numbers are this kind of statement: individually unpredictable, collectively predictable.
friction: Human intuition about probability is poor (the birthday paradox, base-rate neglect, the gambler's fallacy). Independence assumptions are often wrong in systems: failures are correlated (same rack, same deploy, same bug), so 'three replicas each with 1% failure' does not mean a one-in-a-million chance of losing all three. Heavy tails make averages misleading; percentiles (p99, p999) matter more. And statistical significance is easy to misuse in experiments (peeking, multiple comparisons).

@@ infotheory
value: Information theory, founded by Claude Shannon in 1948, measures information precisely and sets the limits of compression and communication. Every compressed file, Wi-Fi link, video stream, error-correcting code and cross-entropy loss in machine learning rests on it. It tells you what is possible before you build anything: no compressor can beat the entropy of the source, and no channel can carry information faster than its capacity.
how: The information in an event with probability p is −log₂ p bits: rare events carry more information than common ones. Entropy H = −Σ p log₂ p is the average information per symbol of a source, and it is the minimum average number of bits per symbol any lossless code can achieve (Shannon's source coding theorem). Huffman coding and arithmetic coding get close to it; modern compressors (Zstd, LZ4) combine pattern matching with entropy coding.
Channel capacity is the maximum rate of reliable communication over a noisy channel; for a channel limited by bandwidth B and signal-to-noise ratio S/N, it is B·log₂(1 + S/N) bits per second (Shannon–Hartley). Shannon's noisy-channel coding theorem says that below capacity, error-correcting codes can make errors as rare as you like. Modern codes (turbo, LDPC, polar) come very close to this limit and run in every phone and SSD.
Related quantities drive machine learning. Cross-entropy measures how many bits you need to encode data from one distribution using a code built for another; minimizing it is how classifiers and LLMs are trained. KL divergence measures the gap between distributions (used in distillation and RLHF). Mutual information measures how much one variable tells you about another (used in contrastive learning objectives). IDF in search ranking is the information content of a term.
How the lower layers add value: probability (Layer 4) is its foundation; and at Layer 5 it connects to physics: Shannon's entropy formula has the same form as Boltzmann's and Gibbs's thermodynamic entropy, and Landauer's principle shows that erasing information has a minimum energy cost, so information is physical.
intuition: If your friend always replies 'fine' when asked how they are, the reply tells you almost nothing. If they reply with something unexpected, you learn a lot. Information is surprise. Compression works by spending few bits on common things and more bits on rare ones, like Morse code giving 'E' a single dot.
friction: Shannon's theory deliberately ignores meaning, which is both its power and its limit; it cannot tell you whether a message is true or useful. Entropy depends on the model of the source: better models compress better, which is why LLMs are also excellent compressors. The limits are asymptotic and assume known statistics; practical systems trade closeness to the limit for speed. And lossy compression (video, audio) needs a second theory, rate–distortion, plus knowledge of human perception.

@@ transistor
value: The transistor is the switch from which every digital computer is built. A modern GPU has over 200 billion of them (NVIDIA's Blackwell packages 208 billion across two dies); a phone chip has tens of billions. Every bit of logic, every bit of SRAM cache and every bit of flash storage is made from transistors or close relatives. Its value is an electrically controlled switch that is tiny, fast, cheap, reliable and needs no moving parts, so that switches can control other switches and form logic.
how: The first transistor (Bardeen, Brattain and Shockley, Bell Labs, 1947) was a point-contact device; today's chips use MOSFETs (metal–oxide–semiconductor field-effect transistors, first made in 1959). A MOSFET has a source and drain, regions of doped silicon, separated by a channel, with a gate above it insulated by a very thin oxide layer. Applying voltage to the gate creates an electric field that draws charge carriers into the channel, letting current flow; removing it turns the channel off. An n-type MOSFET conducts when the gate is high; a p-type when it is low. Pairing them gives CMOS logic: an inverter, NAND and NOR gates, and from those, every circuit. CMOS uses little power when idle because one of each pair is always off.
To keep shrinking transistors, the industry moved from flat (planar) transistors to FinFETs (around 2011, where the gate wraps three sides of a fin) and now gate-all-around nanosheets (Samsung from 2022; Intel and TSMC around 2025), where the gate surrounds the channel,, to keep control of the channel and limit leakage. Transistors are printed by photolithography: light shone through masks onto light-sensitive layers on a silicon wafer, today with extreme-ultraviolet (13.5 nm) light. Copper wires on many layers connect them.
How the lower layers add value: band theory and quantum mechanics (Layer 5) explain why silicon is a semiconductor with a band gap of about 1.1 eV, and why doping with phosphorus or boron creates free electrons or holes; the p–n junction explains the barriers that the gate controls; lithography and materials chemistry build them; and thermodynamics limits how many can switch at once without overheating. Upward, Boolean algebra (Layer 4) describes what networks of these switches compute.
intuition: A transistor is a tap for electricity where turning the handle is itself done with electricity. Because the output of one tap can turn the handle of the next, you can build any logic: 'water flows here only if taps A and B are both open'. Billions of such taps, switching billions of times per second, are a computer.
friction: Moore's law slowed: shrinking now costs more per step, and EUV machines cost hundreds of millions of dollars each. Dennard scaling ended around 2006, so smaller transistors no longer automatically use proportionally less power, which forced multicore designs and 'dark silicon' (not all transistors can be powered at once). At a few nanometres, quantum tunneling lets current leak through the gate and the channel, wasting power and limiting further shrinking. Today's progress comes from new transistor shapes, 3D stacking, chiplets, and specialized accelerators rather than simple shrinking.

@@ queueing
value: Queueing theory is the mathematics of waiting lines, and almost every performance problem in a computer system is a queue: requests waiting for a thread, packets waiting in a router buffer, tasks waiting for an executor, Kafka records waiting for a consumer, disk operations waiting in the device queue. It explains why systems that are '80% busy' feel fine and systems that are '95% busy' fall apart, and it gives simple formulas for capacity planning.
how: Little's law (1961) is the most useful single formula: the average number of items in a system L equals the arrival rate λ times the average time each spends inside W, or L = λW. It holds for almost any stable system. If a service handles 1,000 requests per second with 50 ms average latency, about 50 requests are in flight; if a Kafka consumer group falls behind by 600,000 messages at 10,000 messages per second, the lag is a minute.
For a single server with random (Poisson) arrivals and service times (the M/M/1 queue), utilization ρ = λ/μ, and the average time in the system is 1/(μ − λ), which grows like 1/(1 − ρ). At 50% utilization, waiting roughly doubles service time; at 90%, it is ten times; at 99%, a hundred times. Variability makes it worse: Kingman's formula shows waiting time grows with the variability of both arrivals and service. Multiple servers sharing one queue (like a supermarket with a single line) do much better than separate queues per server. Tail latency in fan-out systems compounds: if one request touches 100 servers, the slowest of 100 dominates.
How the lower layers add value: probability and stochastic processes (Layer 4) model random arrivals and service; and the speed of light (Layer 5) sets a floor under the latency that queueing then adds to.
intuition: A highway works smoothly at moderate traffic; near full capacity, one driver braking causes a jam that lasts long after the cause has gone. Queues behave the same way: as utilization approaches 100%, small random bursts no longer have idle time to drain into, so waits explode.
friction: Real systems violate the textbook assumptions: traffic is bursty and heavy-tailed, service times depend on load (garbage collection, cache misses), and retries add load exactly when systems are overloaded (retry storms, metastable failures). Averages hide tails, so percentiles matter. Still, even rough queueing models give better capacity plans than intuition, and the rule 'leave headroom' comes straight from the 1/(1 − ρ) curve.
