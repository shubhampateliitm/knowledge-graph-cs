@@ levelorder
what: Level-order traversal visits a tree one depth at a time using a queue. At the start of each round, read the queue length n. That n is exactly the number of nodes on this level, so you pop n nodes and push their children for the next round. This avoids storing depths with every node.
signals: "level by level" or "each level" ; "average, sum or maximum of each row" ; "left to right, then next row" ; "right side view" or "zigzag" ; minimum depth of a tree
code:
```python
from collections import deque

def average_of_levels(root: "TreeNode | None") -> list[float]:
    if not root:
        return []
    out: list[float] = []
    q = deque([root])
    while q:
        n = len(q)            # freeze the size: this is one level
        total = 0
        for _ in range(n):
            node = q.popleft()
            total += node.val
            if node.left:
                q.append(node.left)
            if node.right:
                q.append(node.right)
        out.append(total / n)
    return out
```

@@ treebuild
what: To build a balanced search tree from sorted data, pick the middle item as the root. Everything left of it goes in the left subtree and everything right goes in the right subtree. Repeat on each half. Halving each time keeps the height near log n, instead of a chain of height n.

```python
def sorted_array_to_bst(nums: list[int]) -> "TreeNode | None":
    def build(lo: int, hi: int) -> "TreeNode | None":
        if lo > hi:
            return None
        mid = (lo + hi) // 2          # middle item becomes the root
        node = TreeNode(nums[mid])
        node.left = build(lo, mid - 1)
        node.right = build(mid + 1, hi)
        return node
    return build(0, len(nums) - 1)
```

@@ treefromorders
what: Preorder lists the root first, so its first unused value is the root. In the inorder list, everything left of that root belongs to the left subtree, and everything right belongs to the right. def build_tree(preorder: list[int], inorder: list[int]) -> "TreeNode | None":
```python
    pos = {v: i for i, v in enumerate(inorder)}   # value -> inorder index
    it = iter(preorder)
    def build(lo: int, hi: int) -> "TreeNode | None":
        if lo > hi:
            return None
        val = next(it)                # next unused preorder value is the root
        node = TreeNode(val)
        mid = pos[val]
        node.left = build(lo, mid - 1)
        node.right = build(mid + 1, hi)
        return node
    return build(0, len(inorder) - 1)
```

@@ treeiter
what: Recursion uses the call stack to remember where to return. You can do the same job with your own list used as a stack. def preorder_traversal(root: "TreeNode | None") -> list[int]:
```python
    out: list[int] = []
    stack = [root] if root else []
    while stack:
        node = stack.pop()
        out.append(node.val)          # visit the node first
        if node.right:                # right goes in first ...
            stack.append(node.right)
        if node.left:                 # ... so left comes out first
            stack.append(node.left)
    return out
```

@@ treereturn

```python
def diameter_of_binary_tree(root: "TreeNode | None") -> int:
    best = 0
    def height(node: "TreeNode | None") -> int:
        nonlocal best
        if not node:
            return 0
        l = height(node.left)
        r = height(node.right)
        best = max(best, l + r)       # longest path bending at this node
        return 1 + max(l, r)          # what the parent needs
    height(root)
    return best
```

@@ bfsgrid
what: Breadth-first search with a queue explores a graph in rings: all cells at distance 1, then distance 2, and so on. So the first time you reach a cell is by a shortest path, and you can mark it visited at once. Depth-first search gives no such guarantee. Store the distance in the queue with each cell.

```python
from collections import deque

def shortest_path_binary_matrix(grid: list[list[int]]) -> int:
    n = len(grid)
    if grid[0][0] or grid[n - 1][n - 1]:
        return -1
    q = deque([(0, 0, 1)])            # row, col, path length so far
    grid[0][0] = 1                    # mark visited when pushed
    while q:
        r, c, d = q.popleft()
        if r == n - 1 and c == n - 1:
            return d
        for dr in (-1, 0, 1):         # 8 directions
            for dc in (-1, 0, 1):
                nr, nc = r + dr, c + dc
                if 0 <= nr < n and 0 <= nc < n and grid[nr][nc] == 0:
                    grid[nr][nc] = 1
                    q.append((nr, nc, d + 1))
    return -1
```

```python
def flood_fill(image: list[list[int]], sr: int, sc: int, color: int) -> list[list[int]]:
    old = image[sr][sc]
    if old == color:                  # same colour: stop, or it never ends
        return image
    rows, cols = len(image), len(image[0])
    def dfs(r: int, c: int) -> None:
        if not (0 <= r < rows and 0 <= c < cols) or image[r][c] != old:

    return image
```

@@ cooldown
what: When equal tasks must be at least n slots apart, the most frequent task decides the length. from collections import Counter

```python
def least_interval(tasks: list[str], n: int) -> int:
    counts = Counter(tasks)
    top = max(counts.values())                       # highest frequency
    ties = sum(1 for v in counts.values() if v == top)
    # (top - 1) full blocks of n + 1 slots, then one last partial block
    return max(len(tasks), (top - 1) * (n + 1) + ties)
```

@@ eventsim
what: In an event simulation, things happen at known times and you must handle them in time order. Keep waiting events in a heap ordered by the key that decides who goes next. When nothing is ready, jump the clock to the next arrival time instead of ticking one unit at a time. This makes the cost depend on the number of events, not on the size of the time values.
signals: tasks with enqueue time and duration ; "CPU picks the shortest task available" ; "process events in order of time" ; clock values up to 10^9 ; "when the server is idle"
code:
```python
import heapq

def get_order(tasks: list[list[int]]) -> list[int]:
    order = sorted(range(len(tasks)), key=lambda i: tasks[i][0])  # by enqueue time
    heap: list[tuple[int, int]] = []         # (duration, index)
    out: list[int] = []
    t = i = 0
    while len(out) < len(tasks):
        if not heap and tasks[order[i]][0] > t:
            t = tasks[order[i]][0]           # idle: jump to the next arrival
        while i < len(order) and tasks[order[i]][0] <= t:
            j = order[i]
            heapq.heappush(heap, (tasks[j][1], j))
            i += 1
        dur, j = heapq.heappop(heap)         # shortest duration, ties by index
        t += dur
        out.append(j)
    return out
```

@@ huffman
what: When merging two items costs the sum of their sizes, and the merged item can be merged again, always merge the two smallest first. Small items then get merged early and are added into the cost few times. Large items are merged late. A min-heap gives the two smallest in O(log n) each. This is the idea behind Huffman coding.
signals: "cost of joining two pieces is their sum" ; "connect all ropes or sticks with minimum cost" ; "merge files" ; combined result goes back into the pool ; "repeatedly take the two smallest"
code:

```python
import heapq

def connect_sticks(sticks: list[int]) -> int:
    heap = list(sticks)               # copy so the input is not changed
    heapq.heapify(heap)
    total = 0
    while len(heap) > 1:
        a = heapq.heappop(heap)       # two smallest
        b = heapq.heappop(heap)
        total += a + b                # pay for this merge
        heapq.heappush(heap, a + b)   # the new stick joins the pool
    return total
```

@@ kmerge
what: To merge k sorted lists, keep one pointer per list and put each list's current head in a min-heap. Pop the smallest, add it to the output, and push the next item from the same list. The heap never holds more than k items, so each step costs O(log k) instead of scanning all k heads.
signals: "merge k sorted" lists or arrays ; "smallest range" covering lists ; "k-th smallest in a sorted matrix" ; several sorted streams combined into one ; each list is already in order
code:
```python
import heapq

def merge_k_lists(lists: list["ListNode | None"]) -> "ListNode | None":
    # the list index breaks ties, so nodes are never compared
    heap = [(n.val, i, n) for i, n in enumerate(lists) if n]
    heapq.heapify(heap)
    dummy = tail = ListNode(0)
    while heap:
        _, i, node = heapq.heappop(heap)
        tail.next = node
        tail = node
        if node.next:                 # push the next head of the same list
            heapq.heappush(heap, (node.next.val, i, node.next))
    return dummy.next
```

@@ lazyheap
what: A heap can only remove its top item quickly. To delete or change an item from the middle, do not search for it. Leave the old entry in the heap and record the true value elsewhere, such as in a hash map. When a stale entry reaches the top, check it against the map and throw it away. Each entry is discarded at most once.
signals: values can be updated or corrected later ; "remove an arbitrary element" from a priority queue ; "sliding window maximum" with expiring items ; need max and min after changes ; design problem with update and query
code:
```python
import heapq

class StockPrice:
    def __init__(self):
        self.price: dict[int, int] = {}     # timestamp -> true price
        self.latest = 0
        self.lo: list[tuple[int, int]] = []  # (price, time) min-heap
        self.hi: list[tuple[int, int]] = []  # (-price, time) max-heap

    def update(self, timestamp: int, price: int) -> None:
        self.price[timestamp] = price
        self.latest = max(self.latest, timestamp)
        heapq.heappush(self.lo, (price, timestamp))
        heapq.heappush(self.hi, (-price, timestamp))   # old entries stay

    def current(self) -> int:
        return self.price[self.latest]

    def maximum(self) -> int:
        while -self.hi[0][0] != self.price[self.hi[0][1]]:
            heapq.heappop(self.hi)          # stale: price was corrected
        return -self.hi[0][0]

    def minimum(self) -> int:
        while self.lo[0][0] != self.price[self.lo[0][1]]:
            heapq.heappop(self.lo)
        return self.lo[0][0]
```

@@ reach
what: Scan left to right and keep the farthest index you can reach so far. At each index, if it is beyond that reach, you are stuck and the answer is no. Otherwise update the reach with i + nums[i]. You never need to try each jump separately, because any index up to the reach is reachable.

```python
    far = 0                           # farthest index reachable so far
    for i, x in enumerate(nums):
        if i > far:                   # a gap we cannot cross
            return False
        far = max(far, i + x)
    return True
```

@@ regret
what: Make the cheap greedy choice now, but remember it in a heap. If a later choice shows that an earlier one was a poor use of a limited resource, take the earlier one back and swap it. Here, ladders are limited, so they should cover the largest climbs. Keep the biggest climbs on ladders. When there are too many, the smallest climb in the heap is paid with bricks.
signals: limited special resource such as ladders or skips ; "choose which ones to use it on" ; decisions can be undone later ; "maximise how far you get" ; a heap holds past choices
code:
```python
import heapq

def furthest_building(heights: list[int], bricks: int, ladders: int) -> int:
    heap: list[int] = []              # climbs currently covered by ladders
    for i in range(len(heights) - 1):
        climb = heights[i + 1] - heights[i]
        if climb <= 0:
            continue
        heapq.heappush(heap, climb)   # first give this climb a ladder
        if len(heap) > ladders:       # too many: take back the smallest
            bricks -= heapq.heappop(heap)
            if bricks < 0:
                return i              # cannot cross from i to i + 1
    return len(heights) - 1
```

@@ rooms

@@ topk

```python
class KthLargest:
```

@@ twoheaps
what: Keep the lower half of the numbers in a max-heap and the upper half in a min-heap. Their tops are the two middle values. After each insert, balance the sizes so the lower half is equal to or one larger than the upper half. The median is then the top of the lower heap, or the mean of both tops, in O(1).
signals: "median" of a stream ; "find median" after each insertion ; "sliding window median" ; split data into a small half and a large half ; balance two groups by size

```python
import heapq

class MedianFinder:
    def __init__(self):
        self.lo: list[int] = []       # max-heap of the lower half (stored negated)
        self.hi: list[int] = []       # min-heap of the upper half

    def addNum(self, num: int) -> None:
        heapq.heappush(self.lo, -num)
        heapq.heappush(self.hi, -heapq.heappop(self.lo))  # biggest of lower moves up
        if len(self.hi) > len(self.lo):                   # keep lo the same size or bigger
            heapq.heappush(self.lo, -heapq.heappop(self.hi))

        if len(self.lo) > len(self.hi):
            return float(-self.lo[0])
        return (-self.lo[0] + self.hi[0]) / 2
```

```python
def find_maximized_capital(k: int, w: int, profits: list[int], capital: list[int]) -> int:
```

@@ combos
what: To choose k items from n without repeats, build each combination in a path and only pick items after the last picked one. The start index makes each set appear once, in increasing order, instead of once per ordering. This avoids generating every permutation and then removing duplicates.
signals: "all combinations" or "choose k from n" ; order does not matter ; "unique subsets of size k" ; "combination sum" with candidates ; "return all possible" sets
code:
```python
def combine(n: int, k: int) -> list[list[int]]:
    out: list[list[int]] = []
    path: list[int] = []
    def go(start: int) -> None:
        if len(path) == k:
            out.append(path[:])       # save a copy of the path
            return
        for x in range(start, n + 1):
            path.append(x)
            go(x + 1)                 # only larger numbers next
            path.pop()                # undo the choice
    go(1)
    return out
```

@@ perms
what: To build every ordering, fill one position at a time. At each position, try every item that is not yet used. Mark it used, recurse for the next position, then unmark it when you return.
```python
def permute(nums: list[int]) -> list[list[int]]:
    out: list[list[int]] = []
    path: list[int] = []
    used = [False] * len(nums)
    def go() -> None:
        if len(path) == len(nums):
            out.append(path[:])
            return
        for i, x in enumerate(nums):
            if used[i]:
                continue
            used[i] = True            # choose
            path.append(x)
            go()
            path.pop()                # undo the choice
            used[i] = False
    go()
    return out
```

@@ expand
what: A palindrome reads the same both ways, so it has a centre. Try every possible centre, which is one letter or the gap between two letters, giving 2n - 1 centres. def longest_palindrome(s: str) -> str:
```python
    best = ""
    for c in range(2 * len(s) - 1):   # centres: letters and gaps
        l = c // 2
        r = l + c % 2                 # odd centre: l == r; even centre: r = l + 1
        while l >= 0 and r < len(s) and s[l] == s[r]:
            l -= 1
            r += 1
        if r - l - 1 > len(best):     # the match is s[l+1 : r]
            best = s[l + 1:r]
    return best
```

@@ rle
what: Run-length encoding replaces each run of equal characters with the character and its count. A read pointer finds the end of each run, and a write pointer stores the result in the same array. The write pointer never passes the read pointer, so the work is done in place. Length-prefixed encoding is the same idea: write the length first so the reader knows where each item ends.
signals: "compress" a string by counting repeats ; "group of consecutive characters" ; "encode and decode a list of strings" ; in-place with O(1) extra space ; counts of 10 or more need several digits
code:
```python
def compress(chars: list[str]) -> int:
    write = read = 0
    while read < len(chars):
        ch, start = chars[read], read
        while read < len(chars) and chars[read] == ch:
            read += 1                 # find the end of the run
        chars[write] = ch
        write += 1
        if read - start > 1:          # a count is written only when above 1
            for d in str(read - start):
                chars[write] = d
                write += 1
    return write
```
walk: #443 String Compression
step: chars = a, a, b, b, c, c, c. read = 0, write = 0.
step: The run of a has length 2. Write "a" and "2". Now write = 2 and read = 2.
step: The run of b has length 2. Write "b" and "2". Now write = 4 and read = 4.
step: The run of c has length 3. Write "c" and "3". Now write = 6 and read = 7.
step: The array starts with a, 2, b, 2, c, 3, and the function returns 6.
bugs: Writing a count of 1 for a single character, which the problem does not want ; Writing a count of 12 as one character instead of "1" and "2" ; Moving the read pointer by one instead of to the end of the run ; Building a new string, which breaks the in-place rule
cost: O(n) time because the read pointer moves over each character once; O(1) extra space, since only a few pointers and a short count string are used.
