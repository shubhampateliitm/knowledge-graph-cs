@@ catalan
what: Some counts split into a left part and a right part around one chosen element. Fix that element, multiply the ways to build the left side by the ways to build the right side, then add up over every choice. Storing the answer for each smaller size means each size is solved once, not many times.
signals: "number of structurally unique" trees or shapes ; "valid parentheses" pairs counted, not listed ; "ways to split" into two independent parts ; count the answers for n, not print them ; small n but the answer grows very fast
code:
```python
def num_trees(n: int) -> int:
    dp = [0] * (n + 1)      # dp[k] = number of BSTs with k nodes
    dp[0] = 1               # the empty tree counts as one way
    for nodes in range(1, n + 1):
        for root in range(1, nodes + 1):
            left = root - 1             # nodes smaller than the root
            right = nodes - root        # nodes larger than the root
            dp[nodes] += dp[left] * dp[right]
    return dp[n]
```

@@ convexhull
what: The convex hull is the smallest convex shape that holds all points, like a rubber band around nails. Sort the points by x, then walk left to right with a stack. If the last two stack points and the new point turn clockwise, the middle point is inside, so pop it. Do this once for the lower half and once on the reversed list for the upper half.
signals: "smallest fence" or "enclose all points" ; "points on the boundary of the polygon" ; "outermost points" of a set ; "convex polygon" that covers every point ; rubber band, rope or wall around trees
code:
```python
def outer_trees(trees: list[list[int]]) -> list[list[int]]:
    pts = sorted(map(tuple, trees))

    def cross(o, a, b):  # > 0 left turn, 0 straight, < 0 right turn
        return (a[0] - o[0]) * (b[1] - o[1]) - (a[1] - o[1]) * (b[0] - o[0])

    def half(seq):
        h = []
        for p in seq:
            # pop only on a strict right turn, so straight points stay
            while len(h) >= 2 and cross(h[-2], h[-1], p) < 0:
                h.pop()
            h.append(p)
        return h

    hull = set(half(pts)) | set(half(pts[::-1]))
    return [list(p) for p in hull]
```

@@ modinv
what: Under a prime modulus p you cannot divide by a number, but you can multiply by its inverse. By Fermat's little theorem, the inverse of a is a^(p-2) mod p, found fast with pow(a, p-2, p). This lets you compute n! / (k! (n-k)!) mod p, so binomials work even when n! is far too large.

```python
MOD = 10**9 + 7

def number_of_ways(start_pos: int, end_pos: int, k: int) -> int:
    d = abs(end_pos - start_pos)
    if d > k or (k - d) % 2:      # too far, or wrong parity
        return 0
    right = (k + d) // 2          # steps taken toward the target
    fact = [1] * (k + 1)
    for i in range(1, k + 1):
        fact[i] = fact[i - 1] * i % MOD
    # nCk = k! / (right! * (k - right)!), division becomes multiply by inverse
    denom = fact[right] * fact[k - right] % MOD
    return fact[k] * pow(denom, MOD - 2, MOD) % MOD
```

@@ multiples

```python
from math import gcd

def count_different_subsequence_gcds(nums: list[int]) -> int:
    present = set(nums)
    top = max(nums)
    count = 0
    for d in range(1, top + 1):
        g = 0
        for m in range(d, top + 1, d):   # visit d, 2d, 3d, ...
            if m in present:
                g = gcd(g, m)            # gcd of all multiples of d seen
                if g == d:               # cannot get lower than d
                    break
        if g == d:
            count += 1
    return count
```

@@ weightedpick

```python
from bisect import bisect_right

class Solution:
    def __init__(self, w: list[int]):

        total = 0
        for x in w:
            total += x
            self.prefix.append(total)    # end of this item's range
        self.total = total

        r = random.randrange(self.total)         # 0 .. total - 1
```

@@ xortrie
what: A binary trie stores each number as a path of bits from the highest bit down. To maximise x XOR y, you want y to differ from x at the highest bit possible. So at each level, step to the child with the opposite bit if it exists. Otherwise take the same bit. This finds the best partner in about 32 steps instead of scanning all numbers.
signals: "maximum XOR of two numbers" ; "XOR with any element of the array" asked many times ; maximise XOR of a range or path ; numbers fit in 32 bits ; pair that gives the largest bitwise result
code:
```python
def find_maximum_xor(nums: list[int]) -> int:
    bits = max(nums).bit_length()
    root: dict = {}
    for x in nums:                          # insert from the top bit down
        node = root
        for b in range(bits - 1, -1, -1):
            node = node.setdefault((x >> b) & 1, {})
    best = 0
    for x in nums:
        node, cur = root, 0
        for b in range(bits - 1, -1, -1):
            bit = (x >> b) & 1
            if (bit ^ 1) in node:           # opposite bit makes this XOR bit 1
                cur |= 1 << b
                node = node[bit ^ 1]
            else:
                node = node[bit]
        best = max(best, cur)
    return best
```

```python
    def __init__(self, iterator):
        self.it = iterator
        self._load()

    def _load(self) -> None:         # read one item ahead

        self.val = self.it.next() if self.has else None
```

@@ lru
what: A least recently used cache needs get and put in constant time. A hash map finds a node by key at once. A doubly linked list keeps nodes in order from least recent to most recent, so moving or removing a node is O(1) once you hold it. Together they give O(1) for both, while a list alone would need O(n) to find a key.
signals: "least recently used" or "evict the oldest" ; get and put must run in O(1) ; fixed capacity that removes an entry when full ; "recently used" order changes on every read ; design a cache
code:
```python
class Node:
    def __init__(self, key=0, val=0):
        self.key, self.val = key, val
        self.prev = self.next = None

class LRUCache:
    def __init__(self, capacity: int):
        self.cap = capacity
        self.map: dict[int, Node] = {}
        self.head, self.tail = Node(), Node()      # sentinels
        self.head.next, self.tail.prev = self.tail, self.head

    def _remove(self, n: Node) -> None:
        n.prev.next, n.next.prev = n.next, n.prev

    def _add_front(self, n: Node) -> None:         # right after head = most recent
        n.next, n.prev = self.head.next, self.head
        self.head.next.prev = n
        self.head.next = n

    def get(self, key: int) -> int:
        if key not in self.map:
            return -1
        n = self.map[key]
        self._remove(n); self._add_front(n)
        return n.val

    def put(self, key: int, value: int) -> None:
        if key in self.map:
            self._remove(self.map[key])
        n = self.map[key] = Node(key, value)
        self._add_front(n)
        if len(self.map) > self.cap:
            old = self.tail.prev                   # least recent
            self._remove(old)
            del self.map[old.key]
```

```python
class MyCalendar:
    def __init__(self):
        self.starts: list[int] = []     # sorted start times
        self.ends: list[int] = []       # ends[i] belongs to starts[i]

    def book(self, start: int, end: int) -> bool:
        i = bisect_left(self.starts, start)          # first start >= new start
        if i > 0 and self.ends[i - 1] > start:       # earlier event runs into us
            return False
        if i < len(self.starts) and self.starts[i] < end:   # later event begins inside us
            return False
        self.starts.insert(i, start)
        self.ends.insert(i, end)
        return True
```

@@ rankcount
what: To count smaller items to the right, scan from the right and keep a Fenwick tree that counts how many values of each rank were already seen. def count_smaller(nums: list[int]) -> list[int]:
```python
    ranks = {v: i + 1 for i, v in enumerate(sorted(set(nums)))}   # 1-based ranks
    n = len(ranks)
    tree = [0] * (n + 1)
    out = []
    for x in reversed(nums):
        r = ranks[x]
        i, s = r - 1, 0                 # query: how many ranks below r were added
        while i > 0:
            s += tree[i]
            i -= i & -i
        out.append(s)
        i = r                           # update: add this value
        while i <= n:
            tree[i] += 1
            i += i & -i
    return out[::-1]
```

@@ segtree-lazy
what: A range update on a segment tree would touch many leaves if done one by one. Instead, when an update covers a whole node, store the update on that node as a pending tag and stop. Push the tag down to the children only when a later operation needs to look inside that node. Each update and query then costs O(log n).
signals: "add or assign to a whole range" many times ; range update and range maximum or sum together ; squares or boxes dropped over an interval ; "height over a range" after each step ; q operations on n up to 10^5
code:
```python
def falling_squares(positions: list[list[int]]) -> list[int]:
    xs = sorted({x for l, s in positions for x in (l, l + s)})
    pos = {x: i for i, x in enumerate(xs)}
    n = len(xs) - 1                      # cells between neighbouring coordinates
    mx = [0] * (4 * n)
    lz = [0] * (4 * n)                   # pending "raise to at least" tag

    def apply(o, h):
        mx[o] = max(mx[o], h); lz[o] = max(lz[o], h)

    def push(o):
        if lz[o]:
            apply(2 * o, lz[o]); apply(2 * o + 1, lz[o]); lz[o] = 0

    def update(o, lo, hi, l, r, h):
        if r < lo or hi < l: return
        if l <= lo and hi <= r: apply(o, h); return
        push(o); mid = (lo + hi) // 2
        update(2 * o, lo, mid, l, r, h); update(2 * o + 1, mid + 1, hi, l, r, h)
        mx[o] = max(mx[2 * o], mx[2 * o + 1])

    def query(o, lo, hi, l, r):
        if r < lo or hi < l: return 0
        if l <= lo and hi <= r: return mx[o]
        push(o); mid = (lo + hi) // 2
        return max(query(2 * o, lo, mid, l, r), query(2 * o + 1, mid + 1, hi, l, r))

    out, best = [], 0
    for l, s in positions:
        a, b = pos[l], pos[l + s] - 1
        h = query(1, 0, n - 1, a, b) + s
        update(1, 0, n - 1, a, b, h)
        best = max(best, h)
        out.append(best)
    return out
```

@@ segtree-merge
what: Sometimes a node must keep a small summary, not one number. For the longest run of equal letters, a node stores its prefix run, suffix run, best run and size. Two children combine in O(1): the best run may cross the middle if the two letters at the join are equal. A point change then fixes only the O(log n) nodes on its path.
signals: "longest substring of one repeating character" after each update ; longest run, longest subarray or best segment under point updates ; answer must come after every query ; a combine step that needs more than a sum or max ; n and q up to 10^5
code:
```python
def longest_repeating(s: str, query_characters: str, query_indices: list[int]) -> list[int]:
    n = len(s)
    chars = list(s)
    tree = [None] * (4 * n)       # node = (prefix run, suffix run, best run, size)

    def merge(a, b, mid):
        pa, sa, ba, na = a
        pb, sb, bb, nb = b
        pre, suf, best = pa, sb, max(ba, bb)
        if chars[mid] == chars[mid + 1]:       # runs join across the middle
            if pa == na: pre = na + pb
            if sb == nb: suf = nb + sa
            best = max(best, sa + pb)
        return (pre, suf, best, na + nb)

    def build(o, lo, hi):
        if lo == hi:
            tree[o] = (1, 1, 1, 1); return
        mid = (lo + hi) // 2
        build(2 * o, lo, mid); build(2 * o + 1, mid + 1, hi)
        tree[o] = merge(tree[2 * o], tree[2 * o + 1], mid)

    def update(o, lo, hi, i):
        if lo == hi: return                    # a leaf is always (1, 1, 1, 1)
        mid = (lo + hi) // 2
        if i <= mid: update(2 * o, lo, mid, i)
        else: update(2 * o + 1, mid + 1, hi, i)
        tree[o] = merge(tree[2 * o], tree[2 * o + 1], mid)

    build(1, 0, n - 1)
    out = []
    for c, i in zip(query_characters, query_indices):
        chars[i] = c
        update(1, 0, n - 1, i)
        out.append(tree[1][2])
    return out
```

@@ timemap
what: For each key, store its history as two parallel lists in time order: timestamps and values. New sets always have larger timestamps, so the list stays sorted without extra work. To read at time t, binary search for the last timestamp at or before t. This is O(log n) instead of scanning the whole history.
signals: "get the value at or before a timestamp" ; "set" with a timestamp that always increases ; history of a key, or snapshot at a past time ; return an empty string or -1 when nothing is old enough ; many reads against a growing log

```python
from bisect import bisect_right
from collections import defaultdict

class TimeMap:
    def __init__(self):
        self.times = defaultdict(list)     # key -> timestamps, increasing
        self.vals = defaultdict(list)      # key -> values, same order

    def set(self, key: str, value: str, timestamp: int) -> None:
        self.times[key].append(timestamp)
        self.vals[key].append(value)

    def get(self, key: str, timestamp: int) -> str:
        ts = self.times.get(key)
        if not ts:
            return ""
        i = bisect_right(ts, timestamp)    # entries with time <= timestamp
        return self.vals[key][i - 1] if i else ""
```

```python
    WINDOW = 300

    def __init__(self):
        self.q: deque[int] = deque()      # timestamps, oldest first

        self.q.append(timestamp)

    def get_hits(self, timestamp: int) -> int:
```

@@ sweep-active
what: Sweep a line from left to right over the interesting x coordinates, which are the starts and ends of the items. Keep a heap of the items that are open right now, with the best one on top. An item that has ended but is not on top can stay in the heap until it reaches the top, then it is thrown away. At each x, the top of the heap is the answer.
signals: "skyline" or "outline" of buildings ; maximum or minimum among overlapping intervals at each point ; "currently open" intervals ; meeting rooms, tallest building, or earliest deadline at each time ; events sorted by position
code:
```python
import heapq

def get_skyline(buildings: list[list[int]]) -> list[list[int]]:
    xs = sorted({x for l, r, h in buildings for x in (l, r)})
    heap: list[tuple[int, int]] = []        # (-height, right edge)
    i, out = 0, []
    for x in xs:
        while i < len(buildings) and buildings[i][0] <= x:     # buildings that start now
            l, r, h = buildings[i]
            heapq.heappush(heap, (-h, r)); i += 1
        while heap and heap[0][1] <= x:                          # top has ended
            heapq.heappop(heap)
        height = -heap[0][0] if heap else 0
        if not out or out[-1][1] != height:                      # only record changes
            out.append([x, height])
    return out
```

@@ contribution
what: Instead of listing every subarray and finding its minimum, ask how many subarrays each element is the minimum of.
```python
def sum_subarray_mins(arr: list[int]) -> int:
    MOD = 10**9 + 7
    n = len(arr)
    left, right = [0] * n, [0] * n
    st: list[int] = []
    for i in range(n):                          # choices for the left end
        while st and arr[st[-1]] >= arr[i]:
            st.pop()
        left[i] = i - (st[-1] if st else -1)
        st.append(i)
    st = []
    for i in range(n - 1, -1, -1):              # choices for the right end
        while st and arr[st[-1]] > arr[i]:
            st.pop()
        right[i] = (st[-1] if st else n) - i
        st.append(i)
    return sum(arr[i] * left[i] * right[i] for i in range(n)) % MOD
```

@@ bskth
what: To find the k-th smallest value, guess a value v and count how many items are at most v. If the count is below k, the answer is bigger than v. Otherwise the answer is v or smaller.
```python
def kth_smallest(matrix: list[list[int]], k: int) -> int:
    n = len(matrix)

    def count_le(v: int) -> int:          # items <= v, walking a staircase
        r, c, cnt = n - 1, 0, 0
        while r >= 0 and c < n:
            if matrix[r][c] <= v:
                cnt += r + 1              # the whole column above is <= v
                c += 1
            else:
                r -= 1
        return cnt

    lo, hi = matrix[0][0], matrix[-1][-1]
    while lo < hi:
        mid = (lo + hi) // 2
        if count_le(mid) >= k:
            hi = mid
        else:
            lo = mid + 1
    return lo
```

@@ bidirbfs

signals: "shortest transformation sequence" between two words or states ; both the start and the goal are known ; branching factor is large and depth is big ; moves are reversible ; "minimum number of steps" in an implicit graph

```python
def ladder_length(begin_word: str, end_word: str, word_list: list[str]) -> int:
    words = set(word_list)
    if end_word not in words:
        return 0
    front, back = {begin_word}, {end_word}
    steps = 1                                   # words on the path so far
    while front and back:
        if len(front) > len(back):              # expand the smaller side
            front, back = back, front
        nxt = set()
        for w in front:
            for i in range(len(w)):
                for c in "abcdefghijklmnopqrstuvwxyz":
                    cand = w[:i] + c + w[i + 1:]
                    if cand in back:            # the two searches meet
                        return steps + 1
                    if cand in words:
                        words.remove(cand)      # mark as visited
                        nxt.add(cand)
        front = nxt
        steps += 1
    return 0
```

@@ bipartite
what: A graph is bipartite if you can colour nodes with two colours so every edge joins different colours. Colour a start node, then give each neighbour the opposite colour. If an edge ever joins two nodes of the same colour, the graph has an odd cycle and the answer is no. Run this from every uncoloured node so that all components are checked.

```python
def is_bipartite(graph: list[list[int]]) -> bool:
    color = [-1] * len(graph)                  # -1 = not coloured yet
    for s in range(len(graph)):
        if color[s] != -1:
            continue
        color[s] = 0
        stack = [s]
        while stack:
            u = stack.pop()
            for v in graph[u]:
                if color[v] == -1:
                    color[v] = color[u] ^ 1    # opposite colour
                    stack.append(v)
                elif color[v] == color[u]:     # same colour on both ends of an edge
                    return False
    return True
```

```python
    count = 0
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] != "1":
                continue
            count += 1                        # a new, unvisited island
            grid[r][c] = "0"                  # mark visited by sinking it
            stack = [(r, c)]
            while stack:
                x, y = stack.pop()
                for nx, ny in ((x + 1, y), (x - 1, y), (x, y + 1), (x, y - 1)):
                    if 0 <= nx < rows and 0 <= ny < cols and grid[nx][ny] == "1":
                        grid[nx][ny] = "0"
                        stack.append((nx, ny))
    return count
```

@@ cycle-dir
what: In a directed graph, a plain visited set cannot tell a cycle from two paths that meet. Give each node one of three colours: white (not seen), grey (on the current DFS path) and black (finished and known safe). If DFS reaches a grey node, it has walked back into its own path, so there is a cycle. A node is safe only if every path out of it ends without a cycle.
signals: "eventual safe states" ; "does the directed graph contain a cycle" ; every path from the node leads to a terminal node ; deadlock or dependency loops ; "can all tasks finish" in a directed graph
code:
```python
def eventual_safe_nodes(graph: list[list[int]]) -> list[int]:
    color = [0] * len(graph)          # 0 = white, 1 = grey (on path), 2 = black (safe)

    def safe(u: int) -> bool:
        if color[u]:
            return color[u] == 2      # grey here means we found a cycle
        color[u] = 1
        for v in graph[u]:
            if not safe(v):
                return False          # u stays grey: it is not safe
        color[u] = 2
        return True

    return [u for u in range(len(graph)) if safe(u)]
```

@@ topo
what: A topological order lists every node after all the nodes it depends on. Kahn's algorithm counts, for each node, how many prerequisites remain. Put every node with zero into a queue, remove one, and lower the count of the nodes that depended on it. If fewer than all nodes come out of the queue, the rest wait on each other, which means there is a cycle.
signals: "course schedule" or prerequisites ; "build order" or task dependencies ; "can you finish all courses" ; "return any valid ordering" ; detect a cycle in a directed graph
code:
```python
from collections import deque

def can_finish(num_courses: int, prerequisites: list[list[int]]) -> bool:
    adj = [[] for _ in range(num_courses)]
    indeg = [0] * num_courses
    for course, pre in prerequisites:
        adj[pre].append(course)
        indeg[course] += 1                 # one more prerequisite to wait for
    q = deque(i for i in range(num_courses) if indeg[i] == 0)
    taken = 0
    while q:
        u = q.popleft()
        taken += 1
        for v in adj[u]:
            indeg[v] -= 1                  # u is done, so v waits for one less
            if indeg[v] == 0:
                q.append(v)
    return taken == num_courses            # fewer means a cycle
```

@@ ufkey
what: Union-find keeps groups of items, and merges two groups with a small amount of work. When items share a key, such as the same email, an equal sign or a common factor, union them. At the end, items are in the same group exactly when they are linked by a chain of shared keys. Read the groups with find. For "not equal" rules, check them after all unions.
signals: "equations" with == and != ; accounts that share an email belong to one person ; merge items that share a value ; "same group" if linked through a chain ; process all the links first, then answer
code:
```python
def equations_possible(equations: list[str]) -> bool:
    parent = list(range(26))                  # one node per letter

    def find(x: int) -> int:
        while parent[x] != x:
            parent[x] = parent[parent[x]]     # path halving
            x = parent[x]
        return x

    for e in equations:                       # first: apply every ==
        if e[1] == "=":
            parent[find(ord(e[0]) - 97)] = find(ord(e[3]) - 97)
    for e in equations:                       # then: check every !=
        if e[1] == "!" and find(ord(e[0]) - 97) == find(ord(e[3]) - 97):
            return False
    return True
```

@@ ufoffline
what: When queries ask "is there a path using only edges lighter than w", you do not need to answer them in the given order. Sort the edges by weight and the queries by limit. Walk through the queries from the smallest limit, union every edge that is below the limit, and answer with find. Each edge is added once, and the groups only grow.
signals: "path with every edge less than limit" ; many connectivity queries with different limits ; answers do not need to be given in order ; edge lengths or weights bounded per query ; "check existence" of a path under a constraint
code:
```python
def distance_limited_paths_exist(n: int, edge_list: list[list[int]],
                                 queries: list[list[int]]) -> list[bool]:
    parent = list(range(n))

    def find(x: int) -> int:
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    edges = sorted(edge_list, key=lambda e: e[2])
    order = sorted(range(len(queries)), key=lambda i: queries[i][2])
    out = [False] * len(queries)
    e = 0
    for qi in order:                            # smallest limit first
        a, b, limit = queries[qi]
        while e < len(edges) and edges[e][2] < limit:
            parent[find(edges[e][0])] = find(edges[e][1])
            e += 1
        out[qi] = find(a) == find(b)
    return out
```

@@ ufreverse
what: Union-find can merge groups but cannot split them, so deleting items is hard going forward. Run time backwards instead. First remove all the items that will ever be deleted, build the groups, and then add the items back in reverse order. Each deletion in the original order becomes a union in the reversed order. The change in a group's size gives the answer for that step.
signals: "bricks fall" after each hit ; deletions that change connectivity ; "after removing" edges or cells, how many are still connected ; offline: all the removals are known in advance ; union-find has no split
code:
```python
def hit_bricks(grid: list[list[int]], hits: list[list[int]]) -> list[int]:
    R, C = len(grid), len(grid[0])
    roof = R * C
    g = [row[:] for row in grid]
    for r, c in hits:
        g[r][c] -= 1                       # 1 -> 0 (removed), 0 -> -1 (was empty)
    parent, size = list(range(roof + 1)), [1] * (roof + 1)

    def find(x: int) -> int:
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a: int, b: int) -> None:
        a, b = find(a), find(b)
        if a != b:
            parent[a] = b
            size[b] += size[a]

    def link(r: int, c: int) -> None:      # join (r, c) to the roof and to neighbours
        if r == 0:
            union(c, roof)
        for nr, nc in ((r - 1, c), (r + 1, c), (r, c - 1), (r, c + 1)):
            if 0 <= nr < R and 0 <= nc < C and g[nr][nc] == 1:
                union(r * C + c, nr * C + nc)

    for r in range(R):
        for c in range(C):
            if g[r][c] == 1:
                link(r, c)
    out = []
    for r, c in reversed(hits):
        if g[r][c] == -1:                  # nothing was there to put back
            out.append(0)
            continue
        before = size[find(roof)]
        g[r][c] = 1
        link(r, c)
        out.append(max(0, size[find(roof)] - before - 1))   # minus the brick itself
    return out[::-1]
```

@@ ufweight
what: A weighted union-find stores, on each link to a parent, a ratio or an offset. The ratio of x is x divided by its parent. When find follows the path to the root, it multiplies the ratios along the way and shortens the path. Two items in the same group are then related by one division of their ratios to the root.
signals: "a / b = 2.0" style equations with queries ; relation between pairs, such as ratio, difference or distance ; answer "-1" when the relation is unknown ; variables are strings, not numbers ; chains of equations
code:
```python
def calc_equation(equations: list[list[str]], values: list[float],
                  queries: list[list[str]]) -> list[float]:
    parent: dict[str, str] = {}
    ratio: dict[str, float] = {}           # ratio[x] = x / parent[x]

    def find(x: str) -> str:
        if parent[x] != x:
            p = parent[x]
            root = find(p)
            ratio[x] *= ratio[p]           # now x / root
            parent[x] = root
        return parent[x]

    for (a, b), v in zip(equations, values):        # a / b = v
        for x in (a, b):
            parent.setdefault(x, x)
            ratio.setdefault(x, 1.0)
        ra, rb = find(a), find(b)
        if ra != rb:
            parent[ra] = rb
            ratio[ra] = v * ratio[b] / ratio[a]     # ra / rb

    out = []
    for a, b in queries:
        if a in parent and b in parent and find(a) == find(b):
            out.append(ratio[a] / ratio[b])
        else:
            out.append(-1.0)
    return out
```
