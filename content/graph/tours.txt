## Kafka, all the way down | From a commit log to quantum tunneling and the speed of light
kafka | Kafka is a distributed commit log: each topic is split into partitions, and every partition is an append-only file.
commitlog | The log is the source of truth. Consumers keep their own offset and can replay from any point.
partitioning | Partitions give parallelism: different machines own different partitions.
replication | Each partition is copied to followers; a write is committed when the in-sync replicas have it.
raft | Since Kafka 4.0, the controllers agree on cluster metadata with Raft (KRaft) instead of ZooKeeper.
wal | Every write is a sequential append, the cheapest thing a disk can do.
zerocopy | Reads use sendfile: the original Kafka paper notes this avoids two of the four data copies and one of two system calls.
pagecache | Kafka leans on the OS page cache instead of its own cache, so recent data is served from RAM.
tcp | Replication and consumers ride on TCP, whose congestion control is a feedback loop.
queueing | Consumer lag is a queue: as utilization nears 100%, waiting time explodes (Little's law).
combinatorics | Raft is safe because any two majorities overlap, a simple counting fact.
storagedev | The disk is usually NAND flash, which cannot rewrite in place, so sequential writes are kind to it.
tunneling | Flash cells are written and erased by electrons tunneling through a thin oxide, which slowly wears out.
lightspeed | Cross-region replication can never beat about 5 µs per km of fibre.

## Spark, down to the transistor | From a DAG of stages to the band gap of silicon
spark | Spark turns your DataFrame code into a DAG of stages over partitioned data.
mpp | It is a distributed SQL engine: one query runs across many executors.
queryopt | The Catalyst optimizer rewrites the plan and picks join strategies with a cost model.
codegen | Tungsten fuses operators into one generated loop per stage.
shuffle | Wide operations repartition data by key across the network.
relalgebra | Every plan is relational algebra: select, project, join.
hashtables | Hash joins and aggregations are hash tables.
jit | The generated code is JIT-compiled by the JVM into machine code.
pipeline | That machine code runs on pipelined CPUs that hate unpredictable branches.
settheory | Relational algebra is set theory, as Codd showed in 1970.
boolalg | At the bottom, every operation is Boolean logic.
digitallogic | Logic gates implement that Boolean algebra.
transistor | Each gate is a few MOSFET switches.
bandgap | They can switch because silicon has a band gap of about 1.1 eV.

## Delta & Iceberg: the atomic commit | From table formats to entropy
delta | Delta Lake keeps a transaction log next to Parquet files; Iceberg keeps a tree of snapshots.
lakehouse | Together they turn a pile of files into tables with transactions and time travel.
occ | A commit wins only if an atomic put or catalog pointer swap succeeds: optimistic concurrency.
mvcc | Every commit is a new snapshot; old snapshots give time travel.
delvec | Deletion vectors mark deleted rows as a bitmap instead of rewriting files.
columnar | Data files are columnar Parquet.
acid | The guarantees are classic ACID, now on object storage.
isolation | Readers see a consistent snapshot: snapshot isolation.
ordertheory | Serializability means all commits fit into one total order.
encoding | Dictionary and run-length encoding shrink each column.
infotheory | Compression can approach, but never beat, the entropy of the data.
thermo | Shannon's entropy has the same mathematical form as the entropy of physics.

## Elasticsearch: from search box to Aristotle | Inverted indexes, automata and the logic of language
elasticsearch | Elasticsearch spreads Lucene indexes across nodes as shards with replicas.
lucene | Each shard is a Lucene index made of immutable segments that merge over time.
searchengine | A search engine is an inverted index plus relevance ranking.
invindex | The inverted index maps each term to the sorted list of documents containing it.
fst | The term dictionary is compressed into a finite-state transducer.
bm25 | Results are ranked with BM25: frequent in this document, rare overall.
automata | An FST is a finite automaton, the same machinery behind regular expressions.
formallang | Automata recognize formal languages.
infotheory | Rare terms carry more information: IDF is a measure of surprise.
chomsky | Regular languages are the bottom level of Chomsky's hierarchy.
logic | Formal languages and logic are two faces of the same idea.
aristotle | And formal logic begins with Aristotle.

## Pinot: star-trees and the physics of memory | Why columnar real-time OLAP is fast
pinot | Pinot consumes Kafka partitions directly into columnar segments.
rtanalytics | It answers aggregations over fresh data in under a second.
columnar | Each column is stored contiguously.
encoding | Columns are dictionary-encoded and bit-packed.
startree | A star-tree pre-aggregates combinations of dimensions.
bitmap | Inverted and bitmap indexes filter rows with fast set operations.
scattergather | A broker scatters the query to servers and merges the results.
simd | Scans use SIMD instructions over packed values.
memhier | Speed comes from staying in cache instead of going to DRAM.
combinatorics | A star-tree trades space for time by counting dimension combinations in advance.
queueing | Tail latency is set by the slowest server in the scatter.
dram | DRAM is a sea of tiny capacitors that leak and must be refreshed.
maxwell | The gap between cache and DRAM speed comes from wire length and electrical delay.

## PostgreSQL: from WAL to Codd and Frege | Transactions built on logic
postgres | PostgreSQL stores rows in heap pages with B-tree indexes.
oltp | It is built for many small transactions.
btree | B-trees keep lookups to a few page reads.
mvcc | Each update writes a new row version; readers see snapshots.
wal | Every change goes to the write-ahead log first.
relmodel | The relational model: tables are relations, queries are logic (Codd, 1970).
acid | Transactions are atomic, consistent, isolated and durable.
recovery | After a crash, the log is replayed to restore a consistent state.
fsync | Durability depends on fsync reaching stable storage.
settheory | Relations are sets of tuples.
logic | SQL's WHERE clauses are first-order logic.
frege | Predicate logic comes from Frege (1879).
aristotle | Which grew from Aristotle's logic.

## Inside an LLM | From Claude to linear algebra, neurons and Leibniz
claude | Claude, GPT and Gemini are decoder-only transformers.
llm | They predict the next token, trained on huge amounts of text.
bpe | Text is split into sub-word tokens by byte-pair encoding.
embeddings | Each token becomes a vector.
attention | Self-attention mixes information between tokens: softmax(QKᵀ/√d)·V.
kvcache | During generation, past keys and values are cached.
rlhf | After pretraining, models are tuned toward preferred answers with reinforcement learning.
tensorcores | The matrix products run on GPU tensor cores.
dram | Speed is limited by HBM memory bandwidth.
linalg | Attention is linear algebra: QKᵀ is a matrix product.
calculus | Training is backpropagation, which is the chain rule.
probability | Outputs are probability distributions over the next token.
infotheory | The training loss is cross-entropy, from information theory.
distsem | Embeddings rest on the idea that a word is known by the company it keeps.
mccullochpitts | Artificial neurons began as McCulloch and Pitts's 1943 model.
leibniz | And the dream of mechanized reasoning goes back to Leibniz.
landauer | Every bit erased on a GPU becomes heat: computing has a physical cost.

## vLLM: virtual memory for GPUs | How an OS idea made LLM serving cheaper
vllm | vLLM is an LLM serving engine.
llmserving | Serving cost is dominated by memory for the KV cache.
pagedattn | PagedAttention stores the KV cache in fixed-size pages through a page table.
contbatch | Continuous batching adds and removes requests every step.
vmem | This is exactly the OS idea of virtual memory and paging.
queueing | Batching trades latency for throughput, a queueing trade-off.
dram | Pages live in HBM on the GPU.
tsv | HBM is made of memory dies stacked with through-silicon vias.

## MCP agents and the limits of computation | Why sandboxes matter

## Git: names from hashes | From commits to the birthday bound

memhier | RAM is far faster than disk, and cache is faster than RAM.

amortized | Hash tables resize incrementally, keeping average cost low.
queueing | Under high load, latency is a queueing story.
lightspeed | Light travels about 30 cm per nanosecond; distance sets the memory hierarchy.
